Bonekatz Clip Scheduler

Privacy policy

Data handling for the personal Windows desktop app and this information site.

Scope

Bonekatz Clip Scheduler is used by the BoneKatz channel owner. This policy reflects StreamingPC version 0.5.4 and GamingPC version 0.6.8 as inspected in November 2026. Available features differ between versions. The desktop app communicates directly with its connected services; these versions do not send app data to a separate Bonekatz-hosted backend.

Information the app handles

  • Local clip information: selected file paths, file hashes used to detect duplicates, titles, descriptions, tags, cover images, playlist choices, planned times, writing preferences, and social-link settings.
  • YouTube information: channel identity; owned playlist names and IDs; upcoming or active broadcast information; and video metadata needed to display or check changes. Upload-enabled versions also read the selected video's visibility, processing status, and thumbnail information.
  • Twitch information: channel identity, stream status, game-category search results, and title/category/tag information used to check an update.
  • Authorization and operation records: OAuth credentials, local update history, upload receipts where supported, and diagnostic output or errors.

How information is used and sent

The app uses YouTube API Services. Google receives authorization requests and API requests for the features you use. A live update sends the reviewed title, complete description, tags, and optional Gaming category to YouTube for the selected broadcast. Upload-enabled versions send the selected video file, chosen cover, metadata, and playlist choice directly to YouTube. Their upload flow requests private visibility.

Twitch receives authorization requests, category searches, and reviewed channel updates. Choosing Copy notification only places that draft in the Windows clipboard; the app does not send a Twitch go-live notification.

When you choose AI generation, the app sends your supplied text context and relevant writing preferences to OpenAI's API. Live generation includes game, players, context, stable Twitch tags, and mode. Clip generation includes your clip description, game context, and writing style. These code paths do not send video files, cover images, OAuth tokens, playlist caches, or fetched YouTube channel data to OpenAI. Text you type or paste into the context is included, so avoid entering private information you do not want sent.

Generated copy remains editable before an update or upload. The inspected app does not include advertising, analytics telemetry, or a feature that sells account data.

Local storage and security

Queue data, settings, cached playlist information, and operation records are stored in a local SQLite database. Cover files and diagnostic logs are also kept locally. Original videos stay at their selected locations. The live-update history keeps up to 100 entries.

OAuth credentials are stored using the operating system credential vault through keyring, separately from the queue database. Google OAuth client JSON downloaded during setup remains wherever the owner saved it. The OpenAI API key is read from the local environment. The app does not ask for Google or Twitch passwords.

Local metadata and logs are not application-level encrypted. Anyone with sufficient access to the Windows account or its files may be able to read them. Do not publish credentials, downloaded client JSON, local databases, or logs in the website repository.

Retention, revocation, and deletion

The inspected versions retain local data until it is replaced or manually removed. They do not include a timed cache purge or automatic cleanup after account revocation. Removing a clip from the newer version's queue hides its record; it does not erase the database row, original video, or YouTube upload.

You can revoke Google access through Google Account connections. Revocation prevents future authorized requests but does not by itself erase the app's local files or stored credential entry. Contact the app owner for instructions to remove local app records and credentials without deleting original media accidentally. Content already on YouTube must be managed in YouTube Studio.

Current limitation: a clear local-data deletion procedure and a refresh/deletion policy for stored YouTube API data still need to be finalized. This policy does not promise automatic deletion or a retention deadline the current code does not enforce.

This website and other services

This information site is static and adds no forms, embedded players, analytics scripts, cookies, or browser storage. This site is hosted on GitHub Pages, and GitHub processes normal hosting requests under its own privacy statement. Clicking external links takes you to services with their own practices.
